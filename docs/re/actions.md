# ACTIONS workstream – sequencer, text, menus, input, protocol, saves, animation

Conventions as in docs/RE_NOTES.md. "S:" = sub CPU address, "M:" = main CPU address.
Listings: `re/out/dis/actions_sub.asm` / `actions_main.asm` generated by
`python3 re/dis68k.py re/images/sub_prg.bin 6000 're/labels/sub_*.txt' -o re/out/dis/actions_sub.asm`.
Labels: `re/labels/sub_40_actions.txt`, `re/labels/main_40_actions.txt`.
Word RAM (2M mode) is S:0x80000–0xBFFFF = M:0x200000–0x23FFFF (offset S-0x80000 = M-0x200000).

## 1. Input

### 1.1 Main CPU side (M:)
- `pad_read_id` M:0xFF1358: reads the 4-bit Mega Drive peripheral ID of a port (a6=data port)
  using TH toggling (table M:0xFF1386). Result → COMCMD1 hi byte (port 1, M:0xFF0A68) and
  COMCMD1 lo byte $A12013 (port 2). ID 0x0D = 3-button pad. Port 2 ID 1 is treated as the
  light gun (Konami Justifier) – M:0xFF0AAC/0xFF0830 set port-2 ctrl to 0xB0 then.
- `pad1_read` M:0xFF1298 (each VBlank via M:0xFF1284, only if COMCMD1 hi == 0x0D):
  `held = ~((TH0 & 0x30)<<2 | (TH1 & 0x3F))` → bit order **S A C B R L D U** (bit7..0).
  If U and D are both down, U is cleared (`andi #$0E`); if L and R both down, L is cleared (`andi #$0B`).
  COMCMD0 hi ($A12010) = held, COMCMD0 lo ($A12011) = held & ~previous held (newly pressed).
- Light gun (port 2 ID 1): M:0xFF13F6 reads trigger/start bits into $E052/$E053 (edges);
  COMCMD2 lo ($A12015) bit5 = trigger pressed, bit6 = second button pressed; COMCMD3 hi ($A12016)
  = gun X (`$E055<<1`), COMCMD3 lo ($A12017) = gun Y ($E054). X/Y latched by the HV-counter
  routine at M:0xFF148A (installed as level-2/external int vector via $FD14). Only active when
  the sub CPU requests it: COMSTAT7 → M:$E05A (sub writes $7972 = 1 when gun mode, S:0xD770).

### 1.2 Sub CPU side (S:)
- `sub_frame` (`subfn_21` state 0, S:0xD5CC…): `in_copy` S:0xD7B2 copies COMCMD0–3 to
  S:$7980–$7987 each frame ($7980 held, $7981 pressed, $7982/$7983 port IDs,
  $7984/$7985 gun buttons, $7986/$7987 gun X/Y). $798A/$798B = gun X/Y minus $7988/$7989.
- `in_repeat` S:0xDF86: per bit (8 bits of $7980/$7981): on press → counter $7994[i]=0x20 and
  output 1; while held, counter–1, when it hits 0 → reload 4 and output 1. Result in $7993
  (auto-repeat: first repeat after 32 frames, then every 4 frames).
- `in_remap` S:0xDFD6/0xDFF6: logical bytes **$7990 = held, $7991 = pressed, $7992 = repeat**.
  `logical = raw & 0x8F` (Start + D-pad keep their bits) and physical A (bit6), B (bit4), C (bit5)
  are moved to logical bits via the config table S:0xE034 (3 bytes per config, index $78BA):
  config 0: A→6 B→4 C→5; 1: A→6 B→5 C→4; 2: A→4 B→6 C→5; 3: A→4 B→5 C→6; 4: A→5 B→4 C→6; 5: A→5 B→6 C→4.
  Logical bit5 is the "advance/confirm" button used by the message box (S:0x137E8 `btst #5,$7991`).
- Text codes 0xEC/0xEE/0xF0 print the *letter* of the physical button currently bound to logical
  bit 6 / bit 4 / bit 5 respectively (S:0x13B64–0x13BB8; verified against the config table).

## 2. Text renderer

### 2.1 Glyph renderer (low level, "render stream") – `txt_tick` S:0x13BC8
Runs once per sub-CPU frame from `sub_frame` (S:0xD742) while `$9720` (busy) ≠ 0.
State: `$9730` stream pointer, `$9721` delay counter, `$9722` delay reload, `$9723` colour,
`$972A` pen X (pixels), `$972B` pen Y (pixels), `$9728` fixed-pitch flag, `$9729` dirty tile-row mask.
Per frame: if `$972C` ≠ 0 (paused by FA) do nothing. If `$9721` ≠ 0: `$9721--`, stop.
Else loop: `$9721 = $9722`; read byte c:
| byte | effect |
|---|---|
| FF | end of stream: `$9720 = 0` |
| FE n | colour = n (4-bit palette index of pen) |
| FD | newline: Y += 9, X = 0x18; then (same path as 00–1F) `$9725 += 4*0xFD` (byte) and **skips the next byte** |
| FC n | delay = n frames per glyph (`$9722=$9721=n`); then re-checks the counter (so FC n waits n frames) |
| FB x y | pen position X=x, Y=y |
| FA a b | `$972D=a $972E=b $972C=1` → stream pauses (resumed externally; **HYPOTHESIS**: voice/button sync) |
| F9 n | `$972F = n` (unknown use; always 1 in practice) |
| F8 hi lo | word → S:0x13BC4 (unknown) |
| F7 n | fixed-pitch mode `$9728 = n` (advance 9 px, glyphs '1' and 'I' shifted right 1 px) |
| 00–1F n | `$9725 += c*4`, skip one byte (unused in practice) |
| other (20–F6) | draw glyph `c-0x20`, then X += width[c-0x20] (or 9 in fixed-pitch) |
Timing (traced from the code): the counter is reloaded *before* each byte is read and tested
again after each glyph, so `FC 0` draws the whole rest of the stream in the current frame and
`FC n` (n ≥ 1) draws one glyph every n frames (control bytes cost no time). `FC n` itself also
waits n frames. The message box uses `FC 01` (typewriter, 1 glyph/frame); holding confirm (or
`$9727`) forces the reload value to 0 (rest of the line appears at once).

Font: S:0x14B7C, 102 glyphs × 8 bytes, 1 bpp, 8×8, bit7 = leftmost pixel; glyph = code − 0x20
(0x20–0x7F = ASCII, 0x80–0x85 = arrows/markers used by menus). Advance widths: S:0x14EAC (102 bytes).
Dumped/verified visually: `python3 -I re/py/actions_font.py re/images/sub_prg.bin assets/actions/font.png`.

Bitmap target: 4bpp tile bitmap at **S:0xBE000 = M:0x23E000** (Word RAM), 32 tiles wide × 8 tile rows
(256×64 px). Pixel (x,y) address = 0xBE000 + (y>>3)*0x400 + (x>>3)*32 + (y&7)*4 + (x&7)/2; even x =
high nibble. Glyph pixels set to the colour, background pixels untouched. Clear (`txt_clear`
S:0x13D84): fill 0xBE000 with 0 (0x1FE0 bytes) and the last tile (0xBFFE0) with 0x77777777, flag
`$B642E`, then DMA (see §5) Word RAM 0x23FFE0 → VRAM 0x1FE0 (one tile).
Upload: at frame end, dirty tile rows (`$9729`, bit per tile row) are queued for DMA
M:0x23E000+row*0x400 → VRAM row*0x400 (S:0x13F46 via `dma_queue` S:0xE322). So the text window
uses VRAM tiles 0–255 (32×8), row-major; the window's nametable is set up by the main CPU
(see graphics.md).
`txt_window_init` S:0x13D4E: writes 255 nametable words 0x8000..0x80FE (priority bit, tiles 0–254)
+ 0x8000 into S:0xBD000 (=M:0x23D000) and DMAs them to VRAM 0xEC80 (0x200 bytes = 256 entries)
– i.e. the window is a 32×8 block of plane cells at VRAM 0xEC80 (**plane address/position: see graphics.md**).

### 2.2 Script text encoding (SPxx.BIN area 0x3800+, loaded at S:0x1E000)
Texts are addressed by **byte offset from 0x3800** of the script file (S:0x1E000 + off).
Line builder `txt_build_line` S:0x13AC0 copies one line into the render buffer S:$9756…:
| byte | meaning |
|---|---|
| 20–7F | printable ASCII |
| FF | end of message (`$9749 = 1`) |
| F2 | end of line (`$974A = 1`) |
| F6 | end of page (`$974A = 3`, forces page wait) |
| F4 | sets `$97CC = 2` (**HYPOTHESIS**: keeps the talking animation running / voice continues) |
| EC / EE / F0 | letter of the button bound to logical bit 6 / 4 / 5 (see §1.2) |
| F8–FE (not FF) | colour change: emits `FE (c&7)` and remembers it in `$9745` |
Lines are also cut after `$9748` = 0x32 characters.

### 2.3 Message box state machine – sequencer command 0x08 (S:0x135B2, state `$9740`)
Command 08 args: `w0` → `$97CC` (hi byte = flags written by F4; lo byte = **speaker+1**),
`w1` → `$97CE` = text offset. `$9744` = speaker index (lo byte − 1; 0 = narration, 0xFF = none).
Each frame (only when the glyph renderer is idle, `$9720 == 0`; if `$9727` ≠ 0 or the
confirm button (logical bit5 of `$7990`/held) is down, the typing delay is set to 0 = fast text):
- state 9: read args, start window-open effect (`subfn_15` with S:0xECB6) → 10
- state 10: `$97D0 = text off`, clear window (`txt_window_init`), `$9744 = speaker`, reset page
  (`$9746 = $97D0`, colour 1), `subfn_13(0x0F)` (0x14/0x16 if `$7893`=1/2) = main-CPU window effect
  (see §5.3, not a sound) → 2
- state 2: speaker name line: if `$9744 == 0` → `subfn_13(0x15)`, no name; if 0xFF → no name; else name
  string = S:0x13552 + word[S:0x13552 + 2*speaker] (first byte: bit7 set → colour 3, else colour =
  byte&7 and skipped). Render stream `FC 00 F9 01 FB 10 $971D FE c <name> FF` (instant).
  `$9741` (line Y) = `$971D` + 9 → 3
- state 3: build one line: `FC 01 F9 01 FE col FB X Y <≤0x32 chars> FF` with X = 0x28 if narration
  (`$9744 == 0`) else 0x18, Y = `$9741`; delay 1 = typewriter speed. After printing:
  if not end-of-message and not F6: Y += 9; if Y < 0x39 stay in 3 (next line), else → 4
- state 4: start "wait" animation (`$9742=0, $9743=1`), if narration `$83D5 = 2` → 5
- state 5: wait for confirm (`$7991` bit5). While waiting, if speaker ≠ 0 the mouth/cursor
  animation steps through S:0x1391C pairs (frame, duration); when confirm is pressed:
  `subfn_13(0xFE)`; if end of message → 6 else → 7
- state 7: clear window → 8; state 8: effect 0x0F/0x14/0x16 → 2 (next page, name redrawn)
- state 6: finish: `$9740 = 0`, sequencer index += 6, `$97CE=$97CC=0`, if narration `$9717=0xFF`.
Speaker word lo byte: 0 = no name line, 1 = narration (no name, text at X=0x28), n ≥ 2 = name[n-1].
Name table (S:0x13552, 48 word offsets relative to the table, entry 0 empty) begins: "Metal Gear", "Gillian", "Mika", "Togo", "Driver",
"Chief", "Harry", "Napoleon", "Jamie", "Employee", "Man", … "Customer", "Dracula", "Simon Belmont",
"Freeman", "Ivan", "Lisa", "Parrot", "Random". Dump with `re/py/actions_names.py`.

## 3. Action sequencer (S:0xFFC4 `seq_run`)

- Queue S:$9940 (0x200 bytes) of word-aligned commands `[cmd:u16][args…]`; the VM appends with
  a5; terminated by a 0 word (queue is zero-filled by command 00). `$9B40` = byte offset of the
  current command; `$9B44` = busy (set by the VM thread after it finished a statement; the VM thread
  then spins until it is 0).
- Called from `sub_frame` (S:0xD70A) every sub frame while busy. A handler either **completes**
  (jumps to S:0xFFA6/FFAE/FFB6/FFBE = index += 8/6/4/2 then immediately runs the next command in
  the same frame) or **waits** (`rts`, re-entered next frame). Per-command scratch: `$7856` (step),
  `$784E` (timer).
- Arg sizes: "+2" = no args, "+4" = 1 word, "+6" = 2 words or 1 long, "+8" = long+word or 3 words.

| cmd | handler | args | semantics |
|---|---|---|---|
| 00 | 0x1002A | – | end of batch: zero queue, `$9B40=0`, `$9B44=0`, `$7862=0` |
| 01 | 0x1004E | long p | create objects from list p: `[slot][flags25][x.w][y.w][anim_tbl.l][rel.w]`… until 0xFF (object = S:$7A00+slot*0x50, script = p'+rel); same record as DATA scene chunk type 2 |
| 02 | 0x10096 | – | pause all 64 objects (flags25 bit0), clear palette channels, start palette task S:0x100D8 (`03 05 00 3F` = fade to black), wait 0x30 frames |
| 03 | 0x100DC | long p | `subfn_15(p)` start an effect task (table $8E00) |
| 04 | 0x100E8 | – | `$78C3 = FF` (disables object sound op 9D) |
| 05 | 0x100F0 | long p | wait until glyph renderer idle, then start render stream p (`$9730`) |
| 06 | 0x1011A | – | nop |
| 07 | 0x1011E | w n | `$980E = n` (FF→0); `subfn_12(n, d1=1)` (**audio**: start PCM/voice n with done-flag `$980E`) |
| 08 | 0x135B2 | w spk, w text | message box (§2.3); completes when the player dismisses the last page |
| 09 | 0x10164 | w op, w slot | object control (S:0xFDD2), applied to the object and its children (+$4A/+$4C): op0 show (flags25 &= 2, child op 0); op1 pause (flags25 |= 1); op2 flags25=3, +$4E=0 (stop+hide); op3 **wait** until object dead or +$4E bit1 set (then clears it); op4 +$4E = FF; op5 reset (+$4E=0,+$25=0,+$28=+$2A=FFFF) |
| 0A | 0x1016C | – | wait until `$1511E & 0x0F == 0` (PCM voices idle, **HYPOTHESIS**) or 0xE10 frames (60 s) |
| 0B | 0x101A6 | – | wait until CD status (CDBSTAT) hi byte is 0x00 or 0x05 |
| 0C | 0x101BC | w n | if `$7890 == 0` and no PCM voice (`$1511E&7`): `subfn_06(n, -1)` (**audio**: PCM sound effect) |
| 0D | 0x101DC | w n | voice n: step 0 `sub_0150F4(n)`, `$9717=FF`; step 1 idle; step 2 if byte table S:0x13FEC[n] ≠ FF (1198 bytes: voice id → portrait scene number, **not** all FF – corrected, see docs/re/fidelity.md) `$7891 = 1` (main palette split); step ≥3 `$78BC=1`, `subfn_16(table[n])` |
| 0E | 0x10238 | w trk | CD-DA: `cd_play_track(trk)` (CDBIOS 0x12 MSCPLAY1), wait until status == 0x0100 (playing) |
| 0F | 0x1027E | – | scene clear: if `($788B&0x7F)|($788A&1) == 0` → black palettes (S:0xF560) and wait a frame; then `subfn_17` scene reset (kills non-persistent objects, main screen clear request `$7887=1`) |
| 10 | 0x102AC | w n | wait n frames |
| 11 | 0x102C8 | long dst, w file | load file (ISO index) to dst: pause CD, wait drive, `subfn_04`, poll until loaded |
| 12 | 0x10330 | w n | run scene record n of the loaded DATA file (`subfn_16`, see graphics.md §2) |
| 13 | 0x1033C | – | wait until `$980E == 0` (voice/PCM finished, reported by main through COMCMD7 bit7) or 0xA8C frames |
| 14 | 0x10368 | – | nop |
| 15 | 0x1036C | w n, w pos | built-in scene n (table S:0x146CE in SUBCODE) + move object 1 to grid position pos (S:0x144C6 x,y pairs); waits while `$7886` |
| 16 | 0x1037C | – | `txt_window_init` (clear text window) |
| 17 | 0x10386 | – | `$9717 = FF` |
| 18 | 0x10392 | – | `sub_01208E` per frame until `$78AF == 0` (**TODO**: special mini-game, set up by op42 sub 4) |
| 19 | 0x103A2 | – | wait until `$980F == 0` or 0x258 frames |
| 1A | 0x103CE | w | nop |
| 1B | 0x103D2 | w a, w b, w c | wait until CD time `$787A` (CDBSTAT+0x0C, track-relative MSF) ≥ a:b:c |
| 1C | 0x1013E | w n | `$980F = n` (0x3D→0); `subfn_12(n, d1=0)` |
| 1D | 0x103F2 | w | `$7890 = lo byte` (mutes object sound op 9F / cmd 0C) |
| 1E | 0x103FC | w slot | save game to slot (§6) |
| 1F | 0x105DC | – | close animation of objects 58/59 (S:0x13150) |

### 3.1 Who queues what (VM opcode → commands; see script.md for the opcode table)
`op_00` → 09; `op_45` → 09 [3, w]; `op_0F` → 1C; `op_49` → 19; `op_04` → 0D; `op_05` → 0C;
`op_46` → 0A; `op_0A` → 07; `op_47` → 13; `op_0D` → 0E; `op_48` → 0B; `op_4A` → 10;
`op_43/44` → 08 [speaker, text] (op_43 with a nested `20 spk text` list); `op_3D w` → scene
change: `0F`, (`11 [0x28000, w>>8]` if the DATA file differs from `$980A`), `12 [w&0xFF]`;
`op_2B/2C/0B/3A` → `11 [0x1A800, SPfile]` (script file change);
`op_41/42 sub` (table S:0x17492): 0 → 04; 1 → snapshot (S:0x14F12) + 1E [slot]; 2 → 21; 3 → 1F;
4 → `$78E0=w`… + 18; 5 → peek word; 6 → poke word (addr FFFF → `$1512A`); 7 → 1D [w?1:2];
8 → 15 [w,w] (or 09 [2,1] when w=0); 9 → `$9808 = w+2` (VM thread state, see §7);
10 → `$79FE = w` (menu/cursor style); 11 → scene snapshot (w=0) / scene restore (w≠0);
12 → clear game flags (bit array from $9C95); 13 → 1B [w,w,w].

## 4. Menus (command menu, choices)

### 4.1 How the script builds menus (VM side; S:0x16814 loop, handlers in script.md)
Small stacks `[cap:u8][count:u8][u16 items…]` (helpers S:0x107DC get(i), 0x107FE top, 0x10806 push,
0x10816 pop, 0x10778 drop, 0x1082C truncate, 0x10840 clear, 0x10788 contains, 0x1071E push-FIFO):
| addr | cap | role |
|---|---|---|
| $9840 | 8 | menu "floors" (depths below which Cancel cannot go; pushed by op_36, popped by op_39) |
| $9852 | 31 | items collected during the current pass (text offsets) – count `$9853` |
| $9892 | 15 | selection path: chosen item (text offset) per depth – count `$9893` |
| $98B2 | 18 | cross-file call stack (op_0B push, op_3A pop: file, pc) |
| $98D8 | 3 | last 3 statement addresses (FIFO, saved in the save file) |
| $98E0 | 16 | in-file gosub stack (op_0C) |
Execution model (one "pass" = one dispatch of the statement at `vm_pc` $9800):
- `op_38 (item text, body)` at depth d = `$9804`: if d == count($9892) → push `text` onto $9852
  (offer it as a menu item); else if $9892[d] == text → d++, run body, d-- (`$9805=FF` when the
  body ran at the deepest level with nothing collected); else skip.
- "Action" opcodes (those starting with `jsr S:0x16C90`) only fire when no items were collected
  (`$9853 == 0`), no jump is pending (`$9802 == FFFF`) and either `$9804 == $9893` (exactly the
  selected depth) or, after a body ran (`$9805`), `top($9840) < $9804`.
- After the pass the VM waits for the sequencer to drain, then: pending jump (`$9802`) → push old pc
  on $98D8, `vm_pc = $9802`. If items were collected → menu shown (§4.2), result `$79F4`:
  ≥1 → push item[$79F4-1] on $9892 (descend); FF (Cancel) → drop the last selection unless
  count($9893) == top($9840). If nothing was collected → truncate $9892 to top($9840) (back to
  the floor). Clear $9852, loop.
(SCRIPT workstream owns the opcode details; this is the contract the menu UI needs.)

### 4.2 Menu UI (`menu_show` S:0x10CBE, `menu_input` S:0x11004)
- `$79FF < 2` → vertical text list in the text window; otherwise other layouts (S:0x113A0, TODO).
  If ≥ 9 items (S:0x1130A): `$79FE = 3` when the first item text starts with a letter ≥ 'A',
  else 2 (grid/number menus, S:0x11AA8/0x11B7A, **TODO**), and a layout task is queued (cmd 22).
- Layout constants (S:0x10CB8..): normal: page1 items 6, page2 offset 5, 2, 3, max lines 7;
  with `$7893` (wide portrait mode): 5, 4, 3, 4, 6.
- Item line i (render stream at $96E0): `FC 00 F9 01 FE c FB 10 (i*9) <text ≤ 0x20 chars> FF`,
  colour c = 4 (normal) or 1 (highlighted); item text = script text at S:0x1E000 + item.
  With exactly 8 items (or 7 in `$7893` mode with `$9853==7`) paging is used (`$9715` 1/2) and
  arrow items are drawn from S:0x10EFA/0x10F10/0x10F26 (`FB 7C y` + glyphs 0x80–0x85).
- Cursor sprite = object 0 ($7A00): X = 0x10, Y = 0x8F + 9*i (+0x10 in `$7893` mode).
- Input (each frame, S:0x110B0): newly pressed → acts immediately; held: after 32 frames, then
  every 16 frames (8 when `$79FE ≥ 2`). Up/Left = previous (wraps), Down/Right = next (wraps).
  Confirm (`$7991 == 0x20`, exactly) → `$79F4 = cursor+1 (+page offset)`, at depth 0 remember the
  cursor in `$9716`, play SFX 0x1D via cmd 1C. Cancel (`$7991 == 0x10`) → `$79F4 = FF` only when
  depth > 0. Single-item menus ignore movement.
- When the menu opens: `subfn_13(0x0D)` (0x12 in `$7893` mode) = main window effect; `$79FE == 1`
  selects a free pointer mode (S:0x10846: D-pad moves `$96D0/$96D4` in 0x200 steps inside a box,
  cell lookup in map S:0x109E8 (36 bytes/row) → region id `$96DC`; cancel bit4 held confirms).

## 5. Main ↔ sub protocol and frame structure

### 5.1 Frame
- Main VBlank (`vint_handler` M:0xFF06C8): COMCMD4 += 1 (frame counter), then raises sub INT2
  (`ori.w #$8100,$A12000`). The sub level-2 handler (SP `sp_vint` S:0x60BE → `subfn_21` S:0xD4DC)
  runs **one sub frame per main VBlank** (when SP state 6 and the sub flag byte bit1 is clear).
- Sub frame, normal mode (`$FF802F == 0`, S:0xD5CC): update CD status/time ($7876/$787A),
  RNG step (S:0xFD96), wait for Word RAM (`$FF8003` bit1), input (§1.2), `$78B2` = frames elapsed
  (COMCMD4 delta), play-time BCD counter (only in game mode 5), cursor-pointer object (S:0x10990),
  [if no `$7887/$7886` blocking] COMCMD7 sound-done flags (S:0xDF52), **sequencer** (if busy),
  else mode machine `subfn_02` + object animation (S:0xF7F0); then scroll (`subfn_22`), sprite list
  build (S:0xED28), palette channels (S:0xE4B4), effect tasks (S:0xE846), VRAM upload lists
  (S:0xE34E), text renderer (S:0x13BC8), Word RAM status bytes, COMSTAT0 = `$7970`, COMSTAT7 = gun mode.
- The VM runs in the **sub main thread** (SP `sp_main` → `subfn_20` S:0x166BA), not in the
  interrupt; it blocks on `$9B44` (sequencer) and waits with S:0xD4AC (until COMCMD4 changes).

### 5.2 Registers
| reg | dir | use |
|---|---|---|
| COMCMD0 ($A12010) | M→S | pad 1 held / newly pressed (S A C B R L D U) |
| COMCMD1 | M→S | peripheral IDs port1 / port2 |
| COMCMD2 lo | M→S | gun buttons (bit5 trigger, bit6 2nd) |
| COMCMD3 | M→S | gun X (×2) / gun Y |
| COMCMD4 | M→S | frame counter |
| COMCMD5–6 | M→S | bytes from main RAM $FF7F48–4A + counter (M:0xFF4DDE; **HYPOTHESIS**: FM/Z80 sound status) |
| COMCMD7 | M→S | lo nibble change counter; bit7 = voice/PCM ($980E) done, bit6 = $980F done (S:0xDF52) |
| COMSTAT0 | S→M | `$7970` (main: nonzero → VDP mode bit, M:0xFF13BA) |
| COMSTAT3–6 | S→M | plane A X/Y, plane B X/Y scroll (integer part, from `subfn_22`) |

|---|---|---|

## 6. Save system
- Save data = S:$9C00..$9DBF (0x1C0 bytes), built by `save_snapshot` S:0x14F12 (op_42 sub 1):
  | off | content |
  |---|---|
  | 00 | save counter (BCD, ≤ 0x99); 01 = previous value |
  | 02 | play time `$79EA` (4 BCD bytes HH MM SS FF; counted in mode 5 only) |
  | 06 | `$79F0` |
  | 08 | `$7988` (gun calibration) |
  | 0A | bits0–2 button config `$78BA`, bit6 `$78B8`≠0 (gun), bit7 `$78A2`≠0 |
  | 0C | current script file `$980C`; 0E resume pc (bottom of $98E0 or `vm_pc`) |
  | 10 | $98D8 history stack (8 bytes) |
  | 18 | scene word `$980A` (DATA file<<8 | scene) ; 1A `$15120` (PCM-driver value replayed with cmd 0D on load, **HYPOTHESIS**: looping ambient/voice id) |
  | 1C | `$980E`; 1D = `$79EE`&F | (`$79FE`&3)<<4 | `$1512A`<<6 | `$7890`<<7 |
  | 20 | 64 object bytes (bit7 alive, bit6 +$4E bit7, bit4 persistent, bit5 +$26, bits0–3 flags) |
  | 60 | game variable bit array (S:$9C60, 0x160 bytes) |
- Command 1E (S:0x103FC), two back-ends:
  1. sub BRAM (`$CDAC == 0`): BCD-increment counter; if the slot is new check free space with
     `_BURAM` BRMSTAT (d0=1; needs ≥ 0x0E blocks) else error `$79E0=1`; BRMINIT, BRMWRITE
     (d0=4) of name "SNATCHER_0n" (template S:0x10592, n = slot '1'..'4', 0x0E blocks) with
     a1=$9C00, retry up to 8 frames, BRMVERIFY (d0=8); on success set slot bit in `$78B6`,
     `$79E2[slot-1]=1`, `$79E0=0`; failure `$79E0=FF`.
  2. main-side (`$CDAC ≠ 0`): copy $9C00 → S:$B6540, slot → $B6511, slot table `$79E2..8` and
     `$78B6` → $B6508..10, request `$B6516=1`; main code (M:$FFE100, graphics.md "For other
     workstreams") answers `$B6516=FF`, result word in `$B653A` (0 ok, else error → `$79E0`).
- Load: VM state 1 (S:0x16734) with `$785C ≠ 0` restores `$79EA/$79F0` from $9C02, script file
  from $9C0C, `vm_pc` from $9C0E, $98D8 from $9C10, then `save_restore_scene` S:0x1500E
  (scene word → queue 0F/11, `0D [$9C1A]` + `0A` when $9C1A ≠ FFFF, `20 [scene]`, `07 [$9C1C]` if
  nonzero, flags from $9C1D) and object states (cmd 20 → S:0x1507A). `$785C` is set by the
  title-screen code in DATA_D2 (see §7).

## 7. Top-level modes (sub CPU)

### 7.1 Mode machine `subfn_02` S:0xE046 (state `$7842`, sub-state `$7844`, done flag `$7846`), runs in the sub frame
| mode | what |
|---|---|
| 0 | boot: install timer IRQ (GA_TIMER 0x87, level-3 vector `$5F84` → S:0xD48E PCM tick), wait CD, load file 4 = **DATA_D2.BIN** to S:0x28000, wait main ready (`$B6400`) → 1 |
| 1 | `sub_0150F4(0x1E)`, wait PCM idle, then call DATA_D2 code (`jsr ($28008)`) every frame until it sets `$7846` → `$78AD=1` (VM thread may start); if `$785C` (continue) → 7 else 2 |
| 2 | `sub_014A52` every frame until `$7846` → reset scroll, `$B642D=1`, clear objects/palette channels → 7 |
| 3 | soft reset request to main (`$B6402=1`) → 0 |
| 5 | **in game** (VM thread active; play time counts); `$7846` → 6 |
| 6 | load file 0x34 = **DATA_Y16.BIN**, run its code every frame until `$7846` → signal VM thread (`$78AE=FF`) |
| 7 | load PCMLT_01 (0x38) → S:0x50000, PCMDRMDT (0x36) → S:0x55000 → 5, `$78AD=FF` |
| 9–11 | CD drive pause/init → 0 |

### 7.2 VM thread `subfn_20` S:0x166BA (state `$9808`, table S:0x166D4)
| state | what |
|---|---|
| 0 | wait for `$78AD` (from mode machine); FF → `sub_00EC5A`, → 1 |
| 1 | init stacks; new game: clear $9C00 (0x1C0 bytes), load **SP06.BIN (file 0x3F)**, pc = 0; continue: restore from $9C00 (§6) → 2 |
| 2 | statement loop (§4.1) |
| 3 | set by op_42 sub 9 (w=1): `$7846=1`, → 5 (mode machine runs DATA_Y16 code) |
| 4 | (w=2) queue cmd 02, wait `$78AE`, then stop the sub (timer off, `$FF802F=2`) |
| 5 | idle |
So the scenario starts at SP06 offset 0; title screen / intro / ending-like sequences are
**sub-CPU code inside DATA_D2 (title), DATA_Y16, DATA_D0/D1** (graphics.md §2: files with a 3rd
header pointer). These code modules must be reimplemented separately (§9).

|---|---|---|
| 00 | w | 1 = active |
| 02 | w | blink mask: drawn only when `(frame & mask) == 0`; FFFF = never drawn |
| 04 | w | (op A0/A1); byte 05 = draw flags: bit0 H-flip, bit1 V-flip, bit2 add plane-A scroll (COMSTAT3/4), bit3 add plane-B scroll (COMSTAT5/6) |
| 06 | l | X (16.16) |
| 0A | l | Y (16.16) |
| 0E | l | X velocity setting (op 86) ; 12 l = Y velocity setting (op 87) |
| 16 | b | bit7: override sprite palette with bits0–1 (op A7) |
| 18 | w | attribute bits: `(w & 0xFC) ror 3` OR-ed into every sprite attribute word |
| 1C | b | group mask: object skipped when `+1C & $78C6` |
| 20 | l | wait-until CD time (op 99/9A) |
| 24 | b | bits2–3 saved |
| 25 | b | bit0 paused (no script, no motion), bit1 hold (frame visible but script waits / not drawn by sprite builder), bit2 waiting for CD time |
| 26 | b | catch-up: run up to `$78B2` script steps per frame (keeps sync after lag) |
| 27 | b | loop counter (ops 82/83) |

| 2A | w | frame time left |

| 48 | w | parent slot (velocities relative) ; 4A first child ; 4C next sibling |
| 4E | b | bit0 persistent across scene reset, bit1 "signal" (op 98, waited by cmd 09 op 3), bit7 |

### 8.2 Script (`anim_step` S:0xF8C0, opcode table S:0xF924)
Entry = `[b0][b1][w2]` (4 bytes). Per frame (if not paused): `+2A -= 1`; when ≤ 0, advance
(+28 += 1, unless +4F) and execute entries until a frame entry:
- `b0 < 0x80` = **show frame b0** (sprite frame = +2E table[b0]) for `w2` frames if b1 == 0,
  else for a random duration in [b2, b3) (`rand16 * (b3-b2) >> 16 + b2`).
- opcodes (b0 ≥ 0x80): 80 delete self; 81 goto b1; 82 loop: if +27≠b1 {+27++, goto b3} else +27=0;
  83 like 82 with a random count (first time +27 = random(2, b2-b1)); 84/85 move self (and
  children) to absolute X/Y = w2; 86/87 set X/Y velocity = (w2<<16)|(b1<<8) (+ parent);
  88 start palette channel at script+w2 (skipped if `$78CA`); 89 stop all palette channels;
  8A start effect task at script+w2; 8B nop; 8C/8D set scroll X/Y target (plane by b1) = w2 and
  `subfn_13(1)`; 8E/8F set scroll X/Y velocity (8.8) = w2 and `subfn_13(2)`; 90–93 pause self and
  children; 94 b1 unpause object b1; 95 b1 delete object b1; 96 b1 stop+hide object b1;
  97 hold-frame (flags25 bit1) then show frame entry; 98 signal (+4E bit1); 99/9A wait until CD
  time ≥ b1:b2:b3; 9B b1 persistent + `$788B=b1`; 9C +4E bit7, `$788B=+4E`; 9D b1 PCM sfx with
  done flag `$980F` (unless `$78C3`); 9E nop; 9F b1 PCM sfx (if not muted and no voice);
  A0/A1 +04 = w2; A2 wait while `$7886`; A3 `$7866=1`; A4 `$788A` bit0; A5/A6 start built-in
  effect tasks S:0xFC84/0xFCA2; A7 +16 = b1; A8 `subfn_13(b1)`; A9 wait until PCM status bit1;
  AA b1: stopwatch (`$78AA`); AB `$7891=b1`; AC catch-up on; AD b1 start voice/PCM with done
  flag `$980E`; AE `$788A` bit1; AF +1C = b1.
- Display pass (S:0xF854): for active, unmasked objects the current entry's frame (if b0 < 0x80)
  sets +36; if not paused, X += +40, Y += +44.
- RNG `rand16` S:0xFD96 (state $786A–$786D, also stepped once per frame in the sub frame):
  ```
  b[6A] += b[6B]; w[6A] += w[6C]; w[6A] += (w[6C]<<8 | b[6C]); b[6C] += b[6D] (carry → w[6A]++);
  w[6C] += 1 (carry → w[6A]++); return w[6A]
  ```

### 8.3 Sprite list (S:0xED28 → S:$B6200, VDP sprite table format, link = running index 1..64)
Sprite frame = `[n-1:u16]` then n pieces `[dy:i16][size:u16][attr:u16][dx:i16]`:
VDP Y = obj.Y + dy + 0x80, X = obj.X + dx + 0x80 (+ scroll if flags), size/link = size + link,
attr = (attr | obj.+18 bits) ^ (flip bits<<11); with H-flip dx = -dx - (8*(w+1)) where w = size
bits 10–11 (V-flip analogous with bits 8–9). Pieces of object 0x20 position insert the extra
sprite group from S:0xEED0 (pointer/crosshair, `$79EE`). Tile pixel format: graphics.md.

### 4.3 Text-entry menus (`$79FE` = 2 phone keypad, 3 alphabet keyboard; S:0x113A0–0x11E28)
- Selected automatically when a pass collects ≥ 9 items (S:0x1130A): first item text starting
  with a letter → 3, else 2; or explicitly via op_42 sub 10 (`$79FE = w`).
- Keypad (2): render stream S:0x11454 draws `1 2 3 / 4 5 6 / 7 8 9 / * 0 #` at X 0xC9/0xD9/0xE9,
  Y 8/0x18/0x28/0x38 (`FB x y c`), main effect `subfn_13(0x0F)`; max length `$9718` = 10.
  Keyboard (3): effect 0x10 (window), letters A–Z and symbols; max length 0x11.
  Navigation grids: S:0x114DC (keypad) / S:0x11512 (alphabet) – one byte per cell, codes:
  0 wall, 1 separator (skip), 2/3 wrap right/left, 4/5 jump down/up a row, 6 row start,
  7 row end, ≥ 0x20 = character. Row stride `$97F1`, start cell `$97F0`, cursor sprites =
  objects 62/63 (X = col*8 + `$97F7`, Y = row*8 + `$97F8`).
- Keys: D-pad moves; confirm (bit5) appends the character at the cursor to `$97D0[]`
  (special cells 8 = enter, 9 = backspace), cancel (bit4) = backspace, **Start** = enter.
  The typed text is shown on the line Y = `$97F6` (0x18 / 0x30 / 0x40) with '_' placeholders.
- Result (S:0x11AA8): the typed string (FF-terminated, empty → " ") is compared with every item
  collected for this pass (texts at S:0x1E000+item); `$79F4` = index+1 of the first exact match,
  or **1 if nothing matches** (so the script's first item is the "no match" branch).
  `$971A == 1` → match if the item contains the first typed character; after an entry `$971A`
  advances (1 → 2 keeps the same input for the next pass, then resets with `$79FE = 0`).
  `$971E` ≠ 0 (direct-dial) → matching is attempted after each key (table S:0x11938 by first digit).

## 10. Shooting sequences (overview only – **TODO** for a dedicated pass)
- Started by op_42 sub 4 (`$78E0 = stage` 0..0x0E, clears `$78E4/E6/E8/EA`, `$78AF=FF`) + sequencer
  cmd 18, which runs `shoot_tick` S:0x1208E every frame until `$78AF == 0`. Phases `$78E8`
