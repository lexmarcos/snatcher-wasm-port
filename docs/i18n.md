# Translation (pt-BR)

The game text can be shown in Brazilian Portuguese. English stays the default: with the language set to English every output of
the engine is byte-identical to the original (tests: `engine/tests/i18n.rs`, `player_path`, `prompts`).

## How to use it
1. Build once: `scripts/build-web.sh` (it runs `snt i18n-build i18n/pt-BR i18n/build/pt-BR.pack`).
2. Serve: `bun web/server.ts` (it serves `/i18n/pt-BR.pack` and `/i18n/pt-BR/ui.json`; restart a server started before this feature).
3. Open `http://localhost:5300/?lang=pt-BR` or pick **Idioma / Language** in the start overlay or in the menu (Esc). The choice is
   stored in `localStorage` (`snatcher.lang`); `?lang=` overrides it for that visit. It can change during play: the next message or menu is drawn in
   the new language. Debug jump example: `?lang=pt-BR&scene=SP06:0`.
4. Native runs: `I18N_PACK=i18n/build/pt-BR.pack cargo run --release -p snengine --example run -- ...`.

## Files
| path | content |
|---|---|
| `i18n/pt-BR/SPxx.json` | one per script file: `"<offset>": {"h": "<hash of the English string>", "t": "<markup text>"}` |
| `i18n/pt-BR/names.json` | speaker names by speaker number (`snt i18n-names assets/raw/files` lists them) |
| `i18n/pt-BR/ui.json` | strings of the web page (keys = `UI_EN` in `web/src/i18n.ts`; test `web/test/i18n.test.ts`) |
| `i18n/pt-BR/GLOSSARY.md` | glossary, style guide and the record of non-literal adaptations |
| `i18n/build/pt-BR.pack` | generated, not committed |
The English text is **not** stored in the repository: the tools read it from the user's `assets/raw/files` and compare the FNV-1a hash.

## Markup
Printable ASCII and the pt-BR letters are themselves. `{nl}` new line (F2), `{page}` page break (F6), `{auto}` auto-advance (F4),
`{c0}`..`{c6}` colours (F8..FE, `{c1}` normal, `{c2}` button names, `{c3}` key information, `{c4}` alert, `{c6}` narration/caption),
`{btn:EC}` `{btn:EE}` `{btn:F0}` button placeholders (shown as the button icon / letter), `{lb}` `{rb}` literal braces, `{xNN}` any other byte.

## Font
The 102 original glyphs are untouched. Glyph codes 0x86-0xA5 are the button icons, **0xA6-0xC5 are the pt-BR glyphs**
(`core/src/i18n.rs` `PT_GLYPHS`): á à â ã é ê í ó ô õ ú ü ç, the capitals Á À Â Ã É Ê Í Ó Ô Õ Ú Ü Ç, º ª « ». Curly quotes were not added
(use `"` and `'`). `snt i18n-sheet assets/raw/files out.png "text"` renders a sample with the real font and widths.

### Accented capitals (measured, then drawn to fit)
Measurements (`SUBCODE.BIN` font, `core/src/actions.rs` `TextWindow` / `MessageBox`, `engine/src/menus.rs`, `engine/src/game.rs`):

| item | rows of the 8x8 cell (0 = top) |
|---|---|
| original capitals A-Z | ink in rows **0..6** (7 high), baseline = row 6, row 7 always empty |
| original lower case | x-height rows 2..6 (5 high); ascenders b d f h k l (and t from row 1) rows 0..6; descenders g j p q y reach row 7; the dots of i and j are row 0 |
| line pitch | **9 px** in every text window (row 8 is never drawn: one blank row between lines) |
| message box, with name | name line y = 0, x = 0x10; text lines y = 9, 18 .. 54 (6 lines), x = 0x18 |
| message box, narration (speaker 1) / no name (speaker 0) | **first line at y = 0**, x = 0x28 / 0x18, lines up to y = 54 (7 lines) |
| command menu, choice lists, Jordan database lists | line i at y = 9 i (**line 0 at y = 0**), x = 0x10, 7 lines (6 in the wide portrait layout); the highlight bar is a 9 px high sprite (rows 0..8 of the line) |
| keyboard / phone / code entry | ASCII only, fixed pitch, never translated |
| every window | the same 256x64 bitmap; `TextWindow::glyph` clips at the top and bottom of the bitmap, nothing can be drawn above y = 0 |

The accents of a taller glyph (approach A, accent above the cell) do not fit: in four window types the first line starts at y = 0, so rows
-2..-1 would be clipped; on the other lines rows -2/-1 are rows 7/8 of the previous line (row 7 holds descenders, and in menus rows 0..8 are
the highlight bar of that line). **Approach B was chosen for every window**: all pt-BR glyphs stay inside their 8x8 cell, so no window can clip
them or let them touch another line (tested, see below).

Design of the accented capitals (`PT_GLYPHS`):
* baseline = row 6, exactly as the original capitals; row 7 stays empty (only the cedilla of **Ç** uses it);
* body 5 rows high (rows 2..6, the x-height) drawn in the style of the original capital (same bars, serifs and widths), accent 2 rows high in
  rows 0..1, so the glyph spans rows 0..6 like an original capital (same top, same baseline);
* accents: acute `´` and grave `` ` `` are 2-pixel diagonals, circumflex `^` a 2-row caret, tilde `~` the 2-row wave of the lower-case ã, diaeresis `¨`
  two dots in row 0 (row 1 stays empty, so Ü shows a gap). Over the narrow apex of A the acute and grave sit beside the apex (one pixel apart),
  otherwise they would merge into the letter;
* **Ç** is the original C (rows 0..6) plus a cedilla in row 7; advance widths are those of the base letters (A 9, E 8, I 5, O 8, U 9, C 8), so the
  `i18n-check` metrics did not change.

Rejected: a 6-row body with a 1-row accent (rows 1..6 + row 0) keeps the capital taller but the accent is a single pixel on the letter:
É reads as Ė (the original complaint) and acute, grave and circumflex cannot be told apart at 1x. The old drawing (accent rows 0-1, body rows 2..7)
was one pixel below the baseline and overlapped the inter-line row.

Known limitation: the 5-row body is as high as the x-height, 2 px lower than the original capitals; the accent reaches the capital top. In all-caps
menus an accented letter therefore looks a little smaller than its neighbours; there is no free row to do better inside the 8x8 cell.
Lower-case pt-BR letters (accent rows 0..1 over the 5-row x-height) were checked and kept as they were.

Tests: `engine/tests/i18n.rs` `accented_capitals_share_the_baseline_of_the_original_capitals` (last ink row 6, widths, accent rows, Ç = C + cedilla) and
`pt_glyphs_stay_inside_their_line_cell_in_every_window_position` (every pt-BR glyph drawn at every line position y = 0, 9 .. 54 of the window: no
pixel clipped, none outside rows y..y+7); `core/src/i18n.rs` `glyph_art_is_valid`.

## Engine
`sncore::i18n::Translation` is the pack (offset -> translated bytes per SP file, plus speaker names). `Engine::set_language(true)` /
`load_translation(pack)` (wasm: `set_language("pt-BR")`, `load_translation(bytes)`). The VM keeps using the original text offsets (menu paths, CHOICE
matching, saves); only the display side maps an offset to the translated string, which lives after the original text area
(`Translation::extend_area`). A missing entry falls back to the English string, so partial translations work. Menus that read typed text (keyboard /
keypad entry, 9 or more items: SP05 name search, SP09 code entry, ...) are never translated (`i18n-check` rejects them).

## Geometry rules (measured, `snt i18n-stats`)
* Message box: 256 px wide bitmap, text starts at x = 24 (speakers, name line at y = 0, text from y = 9: 6 lines per page), x = 40 for narration
  (speaker 1, 7 lines per page) and x = 24 without a name (speaker 0, 7 lines). A page ends when the next line would start at y >= 57, then
  waits for confirm; more text simply continues on the next page. A line is cut after 50 characters.
* Limits used by the validator: line end x <= 232 (speech), 216 (narration), i.e. symmetric margins; the longest English lines end at 225 / 216.
  Menu labels: start at x = 16, at most 32 bytes, end x <= 240 (the highlight bar width); the longest English label ends at 242.
* Pages: more pages than the English string is a warning, and an error when the string has `{auto}` (timing in action scenes).
* Colours, `{btn:..}`, `{auto}` and `{page}` counts must equal the English string (colours as a sequence).

## Tools (`snt`, `tools/src/cmds/i18n.rs`)
| command | use |
|---|---|
| `i18n-ctx <files> SPnn [from [to]]` | context dump (scene, speaker, voice id, menu path, widths); `I18N_LANG=i18n/pt-BR` adds the PT line |
| `i18n-import <lang> <files> patch.tsv` | merge `SPnn@off<TAB>text` (and `NAME@spk<TAB>text`) into the JSON; a leading `~` reflows the text to the box width |
| `i18n-check <lang> <files> [SPnn..\|all]` | the validator (exit status 1 on failures) |
| `i18n-preview <lang> <files> out.png SPnn [off\|longest:N\|sample:N]` | draws messages / menu items with the real renderer and guide lines |
| `i18n-build <lang> out.pack` | pack for the engine |
| `i18n-status <lang> <files>`, `i18n-stats <files>`, `i18n-sheet`, `i18n-names`, `i18n-kinds` | measuring and bookkeeping |

## Deliberately not translated (counted as "not translatable / kept" in the status table)
* **SP01** is the developer debug menu (`Command Debug`: ACT1 IN, SCENE_QUEEN01, Japanese romaji such as KOUJO/TIKADO, CD-DA test, EVIDENCE pos). It is only reachable with `?scene=SP01:0`
  and has no player-facing text. It stays English; the 17 strings that are shared with real scenes (voiced lines such as "Cu...Cunningham!!") are translated through the duplicate fill.
* Entry-style menus that the VM compares with English data: SP05 name entry, SP09 code/birthmark keyboard, SP18/SP35 Napoleon password words and phone digits, SP16/SP27/SP28 "SAVE n / OVERWRITE SAVE n"
  and the answer lists (BENSON, QUEENS, ...), the SP17/SP34 turbocycle destination lists. The dialogue around them says "(em inglês)" where the player must type English.
* 8 strings in SP02 (song lyrics, a Japanese greeting, silence dots), the JUNKER/JORDAN acronym expansions (SP04, SP06, SP08@42b7), the "Face to face" memo text (kept in English quotes inside the
  translated lines) and product/venue names (Junker's Eye, liquid sky, SNOW-9, Plato's Cavern, Outer Heaven, Moonsalt).
